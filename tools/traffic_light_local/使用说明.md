# 本地红绿灯检测

本程序读取同目录的 `红绿灯测试.png`，使用传统 CV、霍夫圆候选、三灯几何与颜色验证、灯面亮灭判定。它只在本地模拟通行判断，不连接 ROS 或控制 Gazebo 小车。

## 运行

需要 Python 3、NumPy 和 OpenCV：

```powershell
python -m pip install numpy opencv-python
cd D:\GPTProject\ros2\zhihuishequ\code
python traffic_light_cv.py
```

默认每秒重新读取一次图片。可靠绿灯输出：

```text
当前是：绿灯
通行：可通行
通过中.....。结束检测
```

红灯、黄灯或未知状态输出不可通行并等待，继续重读。可以用新图片替换同名文件模拟切换；保存过程中无法读取时按未知处理。建议先保存到其他文件名，再替换，避免读取写入一半的文件。按 Ctrl+C 停止等待。

```text
当前是：红灯
通行：不可通行
等待中.....。
```

图片不变，检测结论通常也不会改变。循环读取一张截图不等于接入实时摄像头，也不等于多帧时序验证。

## 可选参数

```powershell
python traffic_light_cv.py --show
python traffic_light_cv.py --image "另一张图片.png"
python traffic_light_cv.py --max-checks 3 --interval 1
python traffic_light_cv.py --roi-bottom 1
```

`--show` 显示检测窗口；等待时可按 Q 退出，绿灯通过后窗口关闭。默认不弹窗，便于脚本运行。`--max-checks` 仅用于有界测试，不提供时一直等待至绿灯或手动停止。`--roi-bottom` 默认 0.45，即搜索图像上方 45%；设为 1 搜索全图，但背景干扰会增多。

`检测输出/检测标注.png` 保存最近一次可读取图片的标注结果，黄圆为灯泡边界，紫圆为分析区域。`检测输出/检测结果.json` 保存当前状态、原因和各灯面指标。读取失败时 JSON 更新为未知，但旧标注图片不会更新，不能把它当成当前成功读取的证据。

## 参数和验证边界

- 默认参数针对当前 678 × 525 截图设置。霍夫半径随图像短边缩放，不代表自动适应所有拍摄距离。
- 候选必须满足半径近似、三点近似共线、间距近似以及红黄绿颜色组成。不确定或存在多个有效灯组时返回未知。
- 在灯泡半径的 80% 内统计，避开黑框。HSV 高亮阈值当前为 210，高亮占比阈值为 0.15，亮暗 V 通道 80 分位差至少 25。这些是当前图片调试参数，不是通用物理标准，也不是概率置信度。
- 红黄绿各只有一个亮灯候选且通过亮暗对比才输出颜色；当前演示黄灯不放行。
- 已实际验证所提供绿灯图片可通行、读取失败连续等待、空白图未知、有效共线组合通过、非共线组合拒绝。
- 尚无真实红灯和黄灯截图，不能声称已验证其召回率或误放行率。后续需用两处路口的红黄绿图片、角度与距离偏差验证并调整参数。
- 本版按用户要求一旦可靠识别绿灯就结束。接入机器人前仍需增加新图像时间戳检查、时序确认、相关路口选择以及速度控制互锁；不能将重复读取同一图片视为多个独立观测。
